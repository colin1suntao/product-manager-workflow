## 1. 产品概述

### 1.1 产品名称和定位
- **产品名称：** FlowBoard (流动看板)
- **产品定位：** 一款面向小型团队、自由职业者和个人的轻量级、直观的Web端任务管理工具，核心通过看板视图和拖拽交互，实现任务状态的可视化管理，提升个人与团队的工作流效率。

### 1.2 解决的问题和目标用户
- **解决的问题：**
    1.  **任务状态不清晰：** 任务散落在聊天记录、文档或脑海中，缺乏统一、可视化的状态追踪视图。
    2.  **工作流程不直观：** 无法快速了解任务从“待办”到“完成”的整体流转情况及瓶颈。
    3.  **协作成本高：** 团队成员间需频繁口头或书面沟通任务进度，信息同步效率低。
- **目标用户：** 小型项目团队（3-10人）、自由职业者、个人开发者或任何需要管理多个并行任务的个体。

### 1.3 产品愿景和核心价值
- **产品愿景：** 成为最简单、最流畅的任务状态管理工具，让工作流像水流一样清晰可见。
- **核心价值：**
    - **直观：** 看板视图一目了然地展示所有任务及其状态。
    - **高效：** 通过拖拽操作，瞬间完成任务状态的变更。
    - **聚焦：** 帮助用户专注于当前阶段（列）的任务，减少上下文切换。

## 2. 目标用户

### 2.1 用户画像
| 角色 | 特征 | 痛点 |
| :--- | :--- | :--- |
| **项目经理 (小明)** | 管理一个5人开发团队，需要掌控项目整体进度。 | 无法快速看到所有任务的分布和阻塞点；团队成员任务状态不同步，需要反复询问。 |
| **开发人员 (小华)** | 需要同时处理多个开发、测试任务。 | 个人待办事项多，容易遗忘；不清楚自己的任务在项目整体中的优先级。 |
| **自由职业者 (小丽)** | 同时承接多个客户的任务，时间管理要求高。 | 任务来自不同渠道，难以统一管理；容易错过截止日期。 |

### 2.2 使用场景
1.  **每日站会：** 团队成员围绕FlowBoard看板，快速同步昨日完成、今日计划和阻塞任务。
2.  **个人任务规划：** 用户将一周的待办事项添加到看板，并在完成时拖入“完成”列，获得成就感。
3.  **项目需求跟踪：** 将产品需求拆分为任务卡片，从“待开发”拖到“开发中”、“测试中”，直至“上线完成”。

### 3.2 功能详细描述

#### 3.2.1 用户账户管理
- **功能说明：** 提供基础的用户注册、登录、登出功能，用于识别用户和保存其数据。
- **用户故事：** 作为一个新用户，我希望能快速注册并登录，以便开始创建和管理我的任务。
- **验收标准：**
    1. 用户可通过邮箱和密码注册新账户。
    2. 注册成功后自动登录并跳转至主界面。
    3. 已登录用户可通过邮箱和密码登录系统。
    4. 用户可在任何页面登出，登出后跳转至登录页。
    5. 未登录用户访问应用内任何页面，均被重定向至登录页。
- **优先级：** P0

#### 3.2.2 看板视图
- **功能说明：** 应用的核心界面，由多个垂直的“列”（如“待办”、“进行中”、“已完成”）组成，用于代表任务的不同状态。
- **用户故事：** 作为一个用户，我希望一打开应用就能看到一个包含所有任务状态列的看板，以便快速掌握全局。
- **验收标准：**
    1. 默认提供三列：`待办 (To Do)`、`进行中 (In Progress)`、`已完成 (Done)`。
    2. 用户可自定义列的名称（例如改为“设计”、“开发”、“测试”）。
    3. 用户可添加新列（最多不超过10列）。
    4. 用户可删除非默认的列（删除列时，该列下的任务需提示用户移动至其他列或一并删除）。
    5. 列支持横向滚动，以适应屏幕宽度不足的情况。
- **优先级：** P0

#### 3.2.3 任务卡片管理 (CRUD)
- **功能说明：** 对单个任务（卡片）进行创建、读取、更新和删除的操作。
- **用户故事：** 作为一个用户，我希望能方便地创建新任务，并编辑其详细信息，如标题、描述和截止日期。
- **验收标准：**
    1.  **创建 (Create):** 用户可在任一列的顶部或底部点击“+”按钮，输入任务标题后快速创建一张任务卡片。
    2.  **读取 (Read):** 任务卡片在看板中默认显示标题。点击卡片可展开侧边栏或弹窗，查看完整详情（标题、描述、截止日期、创建时间）。
    3.  **更新 (Update):** 在任务详情视图中，用户可编辑任务标题、描述、截止日期。
    4.  **删除 (Delete):** 在任务详情视图中，提供“删除”按钮。删除操作需二次确认（“确定要永久删除此任务吗？”）。
- **优先级：** P0

#### 3.2.4 任务拖拽
- **功能说明：** 用户可通过鼠标拖拽操作，将任务卡片在同一列内排序，或移动到其他列。
- **用户故事：** 作为一个用户，我希望用鼠标拖拽任务卡片，就能轻松地将它从“待办”移到“进行中”，或者调整同一列内任务的优先级顺序。
- **验收标准：**
    1.  **列间移动：** 将任务卡片从一列拖拽至另一列并释放后，任务所属的“状态”自动更新为目标列的名称。卡片视觉上出现在目标列的释放位置。
    2.  **列内排序：** 在同一列内，上下拖拽任务卡片可以改变其显示顺序，此顺序代表任务的优先级或关注顺序。
    3.  **拖拽反馈：** 拖拽过程中，原卡片位置显示为半透明占位符，被拖拽的卡片跟随鼠标移动并有轻微放大/阴影效果，提供流畅的视觉反馈。
    4.  **数据持久化：** 拖拽操作（列间移动或列内排序）完成后，新的状态和顺序立即自动保存至服务器，无需用户手动保存。
- **优先级：** P0
